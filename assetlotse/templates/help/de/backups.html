Unter Administration → Datensicherung wird die Datenbank assetlotse.db {% if f.backup_enabled %}jeden Tag automatisch ab {{ "%02d"|format(f.backup_hour) }}:00 Uhr gesichert{% else %}derzeit nicht automatisch gesichert – schalten Sie Täglich automatisch sichern ein{% endif %}. Das läuft im laufenden Betrieb, jede Sicherung wird auf Beschädigung geprüft. Aufbewahrt werden {{ "die neueste" if f.backup_keep == 1 else "die neuesten" }} {{ f.backup_keep }} (einstellbar 1–100), ältere werden gelöscht.

{% endif %}
  • Jetzt sichern legt sofort eine Sicherung an – sinnvoll vor größeren Änderungen oder einem Update.
  • Jede Sicherung (assetlotse-….db) lässt sich herunterladen oder löschen. Ablage: ./data/backups oder der Ordner aus ASSETLOTSE_BACKUP_DIR (z. B. ein NAS).
  • Schlägt eine Sicherung fehl, erscheint ein Warnzeichen am Menüpunkt und Administratoren bekommen eine E-Mail{% if not f.mail_on %} (sobald der E-Mail-Versand aktiv ist){% endif %}.
  • Gesichert wird die Datenbank. Fotos (./data/images), Logo und secret_key liegen als Dateien in ./data – für einen Umzug den ganzen Ordner mitnehmen.

Datenbank und secret_key gehören zusammen: Spiel eine Datenbank immer zusammen mit ihrer secret_key zurück. Ohne den passenden Schlüssel funktionieren 2FA-Anmeldungen nicht, gespeicherte SMTP-/AD-Passwörter und die vertraulichen Angaben der Gegenstände (z. B. BitLocker-Schlüssel) sind unlesbar, und AssetLotse startet nicht.

Wichtig: Die Sicherungen liegen auf demselben Server und schützen nicht vor einem Festplattenausfall. Kopiert den Ordner regelmäßig an einen anderen Ort – die secret_key dabei getrennt geschützt aufbewahren.

Wiederherstellen (auf dem Server; der aktuelle Stand wird vorher automatisch gesichert):

docker compose stop assetlotse
docker compose run --rm assetlotse flask --app wsgi list-backups
docker compose run --rm assetlotse flask --app wsgi restore-backup DATEINAME.db
docker compose start assetlotse

Alles, was nach der Sicherung passiert ist, geht dabei verloren.
