Updates and emergency commands run on the server, in the folder containing docker-compose.yml. Your own values (port, time zone …) live in .env (ASSETLOTSE_* variables); updates never overwrite it, nor ./data or docker-compose.override.yml.

Updating with update.sh:

./update.sh                        # rebuild and restart the current version
./update.sh assetlotse-X.Y.Z.zip    # install a new package, build, start

The script checks the package, makes a backup, only then swaps the program files (on an error the previous ones are restored), builds the image assetlotse:VERSION (if that fails, the old container keeps running), restarts and waits until the container reports healthy. Options: --no-backup, --no-cache, --prune (also delete the previous image), --no-cleanup (do not clean up), --cleanup (clean up only), --pull (ready-made image from GitHub instead of building locally; the container then follows latest, so other update tools can install new versions too; --version X.Y.Z pins a version), -y (no questions), --help. When a new version starts for the first time, AssetLotse backs up the database itself – also when another tool did the update. Cleanup: after a successful update the zip goes into the archive packages/ (current and previous package are kept, older ones deleted); loose zips, leftovers of aborted updates and older AssetLotse images are removed. Other Docker images are left alone. Back to the previous version: ./update.sh packages/assetlotse-OLD.zip. It needs Docker Compose (the docker compose plugin or the older docker-compose, any version) and unzip. The database is migrated automatically at start-up.

Moving to a new server: always take the whole ./data folder – the database and secret_key belong together. Without the matching secret_key, 2FA, SMTP/AD passwords and the items' confidential details are unreadable.

Reproducible build: the base image and all Python packages are pinned to exact versions (requirements.txt, base image additionally by digest) – every build produces the same image.

Emergency commands – each prefixed with docker compose exec assetlotse docker-entrypoint.sh (going through the entrypoint runs them without root rights like the app, so e.g. backups are not owned by root):

  • flask --app wsgi reset-password admin – new password for a local account (also re-enables it)
  • flask --app wsgi reset-2fa admin – reset the second factor
  • flask --app wsgi create-admin emergency – additional local admin account
  • flask --app wsgi backup / list-backups – back up now / list backups
  • flask --app wsgi send-reminders – send reminders now
  • flask --app wsgi apply-retention – apply the retention period now

Most of this is also available in the interface: reset 2FA and lift sign-in locks in the user's account, Back up now, Send now, Clean up now. The version is shown at the bottom of the sidebar; clicking it shows the licence and source code.
