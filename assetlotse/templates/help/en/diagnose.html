Under Administration → Diagnostics AssetLotse checks the installation and shows findings – for example a missing or old backup, errors when sending e-mail or in Active Directory, access without HTTPS, administrators without a second factor or an incomplete database.

Diagnostic package: Download diagnostic package creates a ZIP file you can pass on when you need help. It contains:

  • summary.txt – version and findings at a glance,
  • diagnose.json – all details: server, Python, time zone, memory, state and structure of the database, backups, e-mail, Active Directory, reverse proxy and HTTPS, settings and .env values, numbers of users, items and loans,
  • log.txt – the newest lines of the program log.

Anonymous: the package contains no records, only counts. Passwords, keys, 2FA data and confidential details (e.g. BitLocker keys) are not even read. Names, user names, e-mail addresses, IP addresses, host names, AD paths and details of items, groups and locations are replaced by placeholders, e.g. user-3, email-2@example.invalid or ip-4 (private). The same value always gets the same placeholder within a package – connections stay visible, there is no mapping table. Settings such as the organization name or texts only show whether they are set.

Feel free to look inside before passing it on – all files are plain text.

If the web interface cannot be reached, create the package on the server:

docker compose run --rm assetlotse diagnose

It is then in ./data/diagnose/.

Program log: in addition to the container output (docker compose logs), AssetLotse writes its messages to ./data/logs/assetlotse.log – at most about 2 MB, older lines are dropped automatically. The file stays on the server; its lines only go into the diagnostic package anonymized.
