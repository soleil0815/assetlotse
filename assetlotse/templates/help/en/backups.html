Under Administration → Backup the database assetlotse.db is {% if f.backup_enabled %}backed up automatically every day from {{ "%02d"|format(f.backup_hour) }}:00{% else %}currently not backed up automatically – switch on Back up automatically every day{% endif %}. This runs while AssetLotse is in use, and every backup is checked for corruption. {% if f.backup_keep == 1 %}Only the newest backup is kept{% else %}The newest {{ f.backup_keep }} are kept{% endif %} (adjustable 1–100); older ones are deleted.

{% endif %}
  • Back up now creates a backup immediately – useful before major changes or an update.
  • Each backup (assetlotse-….db) can be downloaded or deleted. Location: ./data/backups or the folder set in ASSETLOTSE_BACKUP_DIR (e.g. a NAS).
  • If a backup fails, a warning sign appears next to the menu item and administrators get an email{% if not f.mail_on %} (once email delivery is active){% endif %}.
  • The database is backed up. Photos (./data/images), logo and secret_key are files in ./data – take the whole folder when moving servers.

The database and secret_key belong together: always restore a database together with its secret_key. Without the matching key, 2FA sign-ins do not work, stored SMTP/AD passwords and the items' confidential details (e.g. BitLocker keys) are unreadable, and AssetLotse will not start.

Important: backups are stored on the same server and do not protect against disk failure. Copy the folder to another place regularly – and keep the secret_key separately protected.

Restoring (on the server; the current state is backed up automatically first):

docker compose stop assetlotse
docker compose run --rm assetlotse flask --app wsgi list-backups
docker compose run --rm assetlotse flask --app wsgi restore-backup FILENAME.db
docker compose start assetlotse

Anything that happened after the backup was taken is lost.
