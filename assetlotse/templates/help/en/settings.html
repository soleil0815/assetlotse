Administration → Settings controls how AssetLotse works for you. Don't forget Save at the bottom.

  • General: Name (organisation or program) – shown everywhere, “AssetLotse” by default; Default language (currently {{ f.languages.get(f.default_language, f.default_language) }}) – used for visitors whose browser prefers neither German nor English, and for emails to users who have not chosen a language.
  • Inventory visibility: {% if f.catalog_own %}currently staff members see no inventory, only their own items (default){% elif f.catalog_all %}currently everyone sees the whole inventory{% else %}currently staff members only see their groups' items and general items{% endif %}. Issuing is always limited to a person's own groups.
  • Legal: addresses of the Legal notice and Privacy policy. The links appear on the sign-in page, in the sidebar and in every email.
  • Issuing: Default loan period (days) – currently {% if f.loan_days %}{{ f.loan_days }} {{ "day" if f.loan_days == 1 else "days" }}{% else %}0 = open-ended (the default; open-ended loans are never overdue, get no reminders and need no extending){% endif %}. Managers can override it when issuing. Extension by {{ f.extension_days }} {{ "day" if f.extension_days == 1 else "days" }}, at most {{ f.max_extensions }} {{ "time" if f.max_extensions == 1 else "times" }}; Max. items per person {% if f.max_loans %}{{ f.max_loans }}{% else %}unlimited (0){% endif %}.
  • Self-service: Self-service checkout ({{ "on" if f.self_checkout else "off" }}), Self-extension ({{ "on" if f.self_extend else "off" }}), Self-return ({{ "on" if f.self_return else "off" }}). Whatever is off is done by managers.
  • Self-registration – see its own topic.
  • Retention – deletion period for completed loans, currently {% if f.retention_months %}{{ f.retention_months }} {{ "month" if f.retention_months == 1 else "months" }}{% else %}never{% endif %}.
  • Two-factor authentication – requirement and internal network, see its own topic.

Important – the secret_key file: it lives in the data folder (./data/secret_key) and belongs inseparably to the database. It encrypts 2FA secrets, SMTP and AD passwords and the items' confidential details (e.g. BitLocker keys). If it is lost or does not match the database, this data becomes unreadable. So always back it up as well.
